- Query: Enumerate the native local Git panel's reachable actions and execution APIs; identify SSH parity, reusable helpers, and mutation/cancellation/source-ownership constraints.
- Scope: internal, source-only planning for the NOT activated `09-06-native-remote-git` child; output belongs to the supplied active task `09-05-sidebar-agent-status`.

## Findings

The remote block is substantive: `crates/mt-app/src/git_panel.rs:452` identifies SSH projects, `:530` skips discovery, and `:822` renders unsupported. The children and dialogs still call local `mt_project::git` APIs directly. Removing these guards alone would expose local filesystem/Git execution against remote path strings.

### Reuse and Backend Boundary

- **Routing:** `store/identity.rs:349` already builds `ProjectExecutionSnapshot`; missing SSH connection returns an error at `:379`, not Local. `execution_host.rs:77` supplies host/root/worktree/path/backend signatures including configuration fingerprint and epoch; `:325` plans Local/WSL/SSH separately and serializes SSH as quoted `cd ... && exec ...`. Retain current local APIs behind an explicit backend choice; remote failure must never enter them, including dialog and filesystem postcheck paths.
- **Read runner:** `execution_host.rs:370` -> `remote_ssh::bounded_exec` (`remote_ssh/mod.rs:436`) -> `mt_ssh::run_bounded_exec_on_session` (`pool.rs:832`) provides caps, timeout and observed epoch. `worktree_catalog.rs:672` demonstrates this for Git already. This is reusable execution plumbing, not a complete remote panel backend.
- **Mutation runner:** prefer adapting the existing `remote_ssh::run_git(context, cwd, plan)` pattern (`remote_ssh/project_ops.rs:359`, re-exported by `remote_ssh/mod.rs:75`), which requires an expected authenticated epoch, checks the exact session before dispatch (`project_ops.rs:578`), and retains `RemoteMutationOutcome` with bounded output, transport/authority error, fingerprint and epoch (`:104`). Its fixed 180-second/64-KiB limits are onboarding-specific; it has no cancellation handle or selected repository/worktree authority field. Conversely, `execute_host_command` loses dispatch/cleanup state when converting to `CommandOutput` or generic errors (`execution_host.rs:393`); it is insufficient unchanged for mutation recovery.
- **Domain reuse:** `git.rs:30`, `:52`, `:60`, `:81`, `:232`, `:242`, `:255`, `:263` define reusable DTOs. `diff_two_texts` (`:783`), hunk construction and bounded LCS fallback are pure but private; expose/extract narrowly rather than duplicate. `git_changes.rs:128`, `git_history.rs:328` and `git_graph` operate on these DTOs without a transport requirement. Status bit mapping currently depends on libgit2; no CLI status/log/ref/commit-file parser was found in `crates/`.
- **Existing parsers:** reuse `mt_project::worktree::parse_porcelain_with_path_semantics(..., Posix)` (`worktree/mod.rs:47`) and `G::project_worktree_scan` (`git.rs:1406`). `worktree_catalog.rs:745` rejects timeout, truncation, missing exit and malformed captures; text retry requires exit 129 plus unsupported `-z` evidence. `project_ops.rs:120`, `:463`, `:624` already probe canonical repository top/common directories and reject ambiguous path output. Do not mistake worktree porcelain for a file-status parser or substitute all sibling worktrees for panel repo discovery.
- **File/registration helpers:** `remote_ssh::read_file_content` (`files.rs:213`) provides bounded regular-file reads; `paths.rs:8`, `:19`, `:35` provide POSIX path operations. These require adaptation for missing/deleted files, symlinks and multi-command epoch consistency, not blind reuse. `store/projects.rs:641`, `:665`, `:689` supplies `ProjectLocationKey::Ssh` and `register_or_activate_project_with_placement(..., ChildWorktree ...)`; use that host-aware boundary instead of local `add_project_at`.

### Concrete Design Constraints / Risks

1. **Fence dispatch, not just display.** Current `GitScope` contains only worktree/generation/cache flag (`git_panel.rs:82`); store observation compares worktree/path, not SSH fingerprint/epoch (`:264`). A reconnect can preserve both. Capture original project plus full execution source, selected repo top/common directory, per-operation token and branch/hash/path parameters. Revalidate before queued work, confirmation, dispatch and completion. A provisional/persisted binding is not fresh authenticated repository authority; resolve/revalidate against the acquired session before mutations. A connection change requires fresh authority, never same-path local execution.
2. **Separate lifetime from effects.** Current work is detached (`git_changes.rs:496`, `git_panel.rs:723`, `git_worktree.rs:1388`); dropping visibility or closing a dialog does not cancel it. Local CLI timeout only stops `recv_timeout`; the `Command::output` worker continues (`git.rs:1164`). SSH timeout closes a channel, not a proven process-tree rollback (`pool.rs:891`). Model not-dispatched, rejected, running, completed and unknown-effect outcomes; preserve unknown state on lost replies. No automatic replay of commit/pull/discard/worktree mutations after possible dispatch. Cancellation before dispatch can prevent work; after dispatch must stop further steps and reconcile, not report "nothing happened".
3. **One source-owned mutation coordinator.** `run_op` counts but does not serialize mutations (`git_changes.rs:485`); commit only guards another commit (`:572`), and pull/push only guard each other (`git_panel.rs:704`). Switches reset these UI flags while prior operations continue. Serialize conflicting writes across Changes/Sync/Worktree Management by authenticated repo/common-dir and affected worktree; shared refs/catalog changes span linked worktrees. Track a distinct operation token through busy indicators/timers, including same-worktree repo A-B-A, where panel sync lacks a repo-generation token. External Git can still race: handle index locks, changed HEAD and changed files explicitly.
4. **Reconcile partial and late mutations.** Existing stable-worktree refresh logic (`git_panel.rs:471`, `:504`; `git_changes.rs:329`) is reusable only after adding host/repository authority checks. Do not restore Loading into cached state (`git_panel.rs:169`; `git_changes.rs:337`). Pull can fetch or leave conflicts before nonzero exit; discard is multi-step; hooks can change files before commit failure; worktree creation can leave partial state. Refresh source-owned status/HEAD/refs/inventory after known or possible effects, not only `is_ok()` as current sync does (`git_panel.rs:744`, `:758`). An old completion may mark its matching stable bucket dirty, but cannot overwrite another source or authorize a new write.
5. **Dialogs need source and instance ownership.** Changes menus/confirmation and history opening already capture owners (`git_changes.rs:538`, `:1040`; `git_history.rs:349`). Diff dialogs retain only path/hash plus file request counter (`git_diff.rs:1050`, `:1477`); Worktree Management receives `project_id=None` from the Git panel and later falls back to active project, including post-create registration (`git_worktree.rs:842`, `:1436`). Add source/lifetime fences throughout; a closed dialog must not register/activate projects later. `prompt::open_guarded_with_close` (`prompt.rs:59`) offers invalidation hooks, while `close_guarded` only checks kind/top-of-stack (`:94`): an old completion must not close a newly opened instance of the same kind.
6. **Mutation scope and path safety.** Build allowlisted structured Git argv and quote only at the SSH boundary (`execution_host.rs:421`); shell quoting does not neutralize Git option parsing or pathspec magic. Use literal path arguments, option terminators where applicable, validated refs/object IDs, and host POSIX containment with exact source checks. Do not normalize backslashes/case using client OS rules. Selected repositories can be ancestors/children of the configured folder; linked-worktree targets can be siblings. Validate each against its proper repository/explicit creation target, not an indiscriminate project-root prefix. Remote SFTP cannot eliminate same-account path-replacement races.
7. **Destructive cleanup is not discovery.** Prune's local postcheck and local-only project lookup would be dangerous when enabled for SSH (`git_worktree.rs:1748`; `store/projects.rs:124`). Require a current complete remote inventory and unambiguous remote absence, preserve invalid/offline configuration unless the dedicated cleanup is justified, and preserve visibility policy. Removal currently disposes terminals before Git succeeds (`git_worktree.rs:1682`); planning must explicitly bound that side effect to the confirmed target and prohibit collateral PTY/config deletion on stale or uncertain work.
8. **Keep errors and limits truthful.** Status/discovery failures currently clear rows and log (`git_changes.rs:455`; `git_panel.rs:571`); remote failure cannot masquerade as clean/no repository. Keep source-owned last-known data marked unavailable and disable mutations without current authority. Parse complete machine output before lossy conversion; handle record framing, rename pairs, whitespace/newlines, invalid UTF-8, empty repositories and unsupported Git capabilities explicitly. Bound both old/new blob reads before allocation: current 1-MiB checks are uneven (`git.rs:716`, `:727`, `:802`, `:1093`). The global PTY tap is only a refresh hint, not source evidence (`git_watch.rs:57`, `:118`); coalesce host reads and reconcile mutations directly.

Git execution must retain the execution host's own hooks, signing, user/config and credential behavior (`git.rs:10`, `:1297`), separate from Tasks account choice. The current local CLI uses null stdin (`git.rs:1168`); SSH exec does not explicitly send stdin EOF in the inspected runner. Define bounded noninteractive/prompt failure behavior without silently disabling hooks or changing Git credentials.

## Caveats / Not Found

- This is a native Rust source inventory, not behavior inferred from legacy TS comments or a runtime reproduction. No build, Cargo metadata, test, fixture, probe, lint, formatter, codegen, automated check, app launch, Git operation, real remote command, credential probe or CI dispatch was run. The only file written is this report; no child activation or product/spec/PRD/task metadata edit occurred.
- Remote status/history/ref/commit-file parsing and a complete cancellable source-owned Git panel backend were not found. The existing SSH mutation pattern is a starting point, not turnkey panel parity. Existing source has edge cases to resolve deliberately: an unstaged deleted file reaches `std::fs::read(...)?` (`git.rs:1093`), while old diff blobs lack the newer-side size guard. Workflow parity should not accidentally preserve such failures as an SSH requirement.
- Worktree Management is reachable from the existing Git context menu, so its actions cannot silently disappear from the acceptance matrix. If its remote mutations are deferred, that must be an explicit approved scope/capability decision, not a local fallback.
- Future verification must be Actions-only: Local/SSH same-path isolation; project/repo A-B-A; config/epoch replacement before dispatch and after dispatch; close/reopen/cancel; concurrent and partially completed writes; status/rename/unborn/merge-history/diff limits; and remote prune/removal without collateral configuration or terminal loss. No such results are claimed here.
